# cadence sensor ハードウェア

基板は2種類あって、ボード定義もそれぞれ分けてある。

| board | 実体 | 用途 |
|---|---|---|
| **`cadence_v1`** | 本番基板 v1（`KiCad/BikeSensor`、15×33 mm） | **これが本命** |
| `cadence_rft` | RideFormTracker PCB v1.0 流用 | 最初のブリングアップ。残してある |

`src/` は共通。**違いは DTS だけ**で、SPI・両 INT・水晶・USB・SWD は完全に同一。

---

## 本番基板 v1（board = `cadence_v1`）

回路は `KiCad/BikeSensor/`（`BikeSensor.kicad_sch` + `Power.kicad_sch`）。
以下のピンは回路図からネットを抽出して確認したもの。

### 使うピン

| nRF52840 | 信号 | 接続先 |
|---|---|---|
| P0.06 | SPI MOSI | LSM6DSV SDA/SDI |
| P0.04 | SPI MISO | LSM6DSV SDO/SA0 |
| P0.08 | SPI SCLK | LSM6DSV SCL/SPC |
| P1.09 | SPI CS | LSM6DSV CS |
| P0.26 | IMU_INT1 | LSM6DSV INT1（wake-up） |
| P0.05 | IMU_INT2 | LSM6DSV INT2（未使用） |
| **P1.11** | **SOFT_LATCH** | **LDO の EN を R12 100k 経由で保持。HIGH で電源維持** |
| **P1.13** | **SW_READ** | **SW2 を 100k/330k で分圧。押されている間 HIGH** |
| **P0.28** | **BAT_CHECK** | **電池電圧 1:1 分圧（R10/R11 1M+1M）。AIN4 = ADC 可** |
| P0.30 | LED_R | 赤 LED（D5）。**カソード GND ＝ アクティブ HIGH** |
| P0.31 | LED_B | 青 LED（D3）。同上 |
| P0.00/P0.01 | XL1/XL2 | 32.768 kHz 水晶 |
| D+ / D- | USB | USB-C |
| SWDIO/SWCLK | SWD | U5 ヘッダ |

緑 LED は無い（LED は赤・青の2個。D8 の黄色は MCP73831 の STAT 直結で MCU からは
触れない）。`src/main.c` は `led-green` エイリアスの有無を見て、無ければ起動完了の
点滅を青に振る。

### IMU は LSM6DSV320X（WHO_AM_I = 0x73）

v1 に載っているのは **LSM6DSV320X**。ブリングアップ基板の LSM6DSV16B（0x71）とは
別の ID を返すので、ドライバは 0x70 / 0x71 / 0x73 の3つを受ける。

ST の `lsm6dsv*_reg.h` を**ドライバが触る全レジスタについて突き合わせた**結果、
実質的な違いは2つだけだった:

| | 16B | 320X |
|---|---|---|
| WHO_AM_I | 0x71 | **0x73** |
| 加速度出力 0x28 | **OUTZ_L_A**（軸が逆順） | OUTX_L_A（正順） |

CTRL1 / CTRL3 / CTRL8、FS_XL の符号化（±8g = 0x2）、感度 0.244 mg/LSB、
6D と inactivity のブロック、MD1_CFG の INT1_6D ビット位置は**全部同じ**。
`TAP_THS_6D` の bit7 は 320X では `d4d_en` だが 0 を書く＝6D なので意図通り。
`INACTIVITY_THS` の bit6/7 は 320X では高g shock の割り込みルーティングだが、
やはり 0 を書くので無効のまま。

**軸逆順は 16B だけの仕様**（0x70 系も 0x73 系も正順）。旧基板では X と Z が
入れ替わって読めていたが、ケイデンス検出は AC エネルギー最小の軸を回転軸とみなす
＝軸の並べ替えに不変なので、実走で問題が出なかった。ドライバ側で 16B のときだけ
戻すようにしたので、今はどの品種でも X,Y,Z が正しく返る。
**ボディトラッカーやラケット用に転用するときはこれが効く。**

320X は高gチャンネル（±320 g）を別に持つが、リセット後は `CTRL1_XL_HG` が
パワーダウンなので触らなければ存在しないのと同じ。低g側は 16B と完全に同じ挙動。

### 電源が自分でスイッチされている（重要）

```
+BATT ── SW2 ──┬── D2 ──┬── LDO_EN (U9 TPS7A0233)
（モーメンタリ）  │        │
             R13 100k  R12 100k
               │        │
            SW_READ  SOFT_LATCH (P1.11)
               │
             R15 330k
               │
              GND
```

- SW2 は**モーメンタリ**。押している間しか EN が上がらない
- 離すまでに **P1.11 を HIGH にしないと電源が落ちる**（＝MCU 自身が死ぬ）
- `src/main.c` の `power_latch_init()` が main の先頭でこれをやる
- 押されていない・VBUS も無い、なら**わざとラッチしない**。ESD やリークで
  勝手に起動した場合にそのまま切れる

**VBUS は EN のどこにも繋がっていない**（回路図からネットを抽出して確認済み。
`+5V` が現れるのは充電器 U7 の VDD だけ）。帰結:

- **USB を挿しただけでは起動しない。** MCU に電源が無いのでラッチを立てられない
- ただし**充電はされる**。MCP73831 は MCU と無関係に動き、D8 も点く
- 低電圧カットオフで落ちた後も同じ。USB で充電はできるが、**復帰にはボタンが要る**

逆に、すでに起動している状態での再起動（`r`、SMP 更新後のリセット）では VBUS が
唯一の手掛かりになるので、ラッチ条件に入れてある。

### 低電圧カットオフ

`src/battery.c` の曲線テーブルで **0% になったら**電源を切る（`src/main.c`）。
閾値の mV をこちら側に書かないのは、テーブルを触ったときに二重定義がズレるから。
**0% の定義はテーブルただ一箇所**。

1分ごとのサンプルが **5回連続**で 0% のときだけ実行する。送信中の瞬間的な落ち込みで
ライドを終わらせないため。USB 接続中は実行しない（充電中で読み値が高く出るうえ、
充電器の故障は「電池が上がらない」という形で現れるので、そこで自分から落ちると
診断できなくなる ── まさに今朝の PROG 断線がその状況だった）。

LiPo の保護 IC（2.4〜2.5V）は**安全のための最後の砦**であって寿命管理ではない。
そこまで毎回使い切るのが一番電池を痛める。

### リブートを跨ぐ問題と、その対策

ソフトリセットで nRF52840 の GPIO はリセットされる（Hi-Z に戻る）。EN ノードには
コンデンサが無い（寄生 ~10 pF）ので、LDO の I_EN 10 nA で引かれると
**数 ms で 1.1 V の閾値を割る**。一方で:

| 保持が必要な時間 | |
|---|---|
| リセット → コードが走り出すまで | ~1 ms |
| MCUboot のイメージ検証 | ~100 ms |
| **MCUboot のイメージスワップ（USB 更新時）** | **~20 秒** |

放っておくと `r` も SMP 更新も電源断になる。そこで **`board.c` を MCUboot にも
リンクしてある**性質を使い、`SYS_INIT(PRE_KERNEL_1)` で **MCUboot 側でも P1.11 を
HIGH にする**。これで残る穴は最初の ~1 ms だけになり、寄生容量の保持時間と同じ
オーダーに収まる。

board.c 側のラッチは**無条件**。「起動して良い理由があるか」の判断は
`src/main.c` の `power_latch_init()` 一箇所だけに置く（ブートローダとアプリに
判断を二重に書くと必ずズレる）。ESD で起動した場合は MCUboot が一旦保持し、
アプリが理由なしと判断して落とす ＝ **1ブート分（~0.4 µAh）の無駄で済む**。

> **ラッチを「一旦 LOW にしてから判断」してはいけない。** ラッチの解放は EN を
> 保持しなくなるだけでなく、**R12 100k を通して能動的に放電する**。10 pF に対して
> τ = 1 µs なので、判断している間に電源が落ちる。floating 時の nA リークで
> 落ちるのと比べて5桁速い。この落差が意図的な電源断をキビキビさせている当のもの
> なので、「判断中だけ LOW」は電源断そのものになる。`power_latch_init()` は
> **先に判断してから1回だけ駆動する**。

それでも不安定なら **EN–GND に 1 µF** を足すのが確実（リークが nA なので数百秒
保つ。意図的な電源断は R12 でアクティブに引くので 100 ms）。0402 を手はんだで
後付けできる。

### 充電回路（MCP73831, U7）

| | |
|---|---|
| 充電電流 | **R14 = 10 kΩ on PROG → I = 1000/R = 100 mA** |
| D8（黄色 LED） | VDD → R20 2k → アノード、カソード → STAT。STAT が LOW を引くと点灯 |
| 電池 | EEMB LP401730、公称 150 mAh（4.3 × 17.5 × 31 mm） |

100 mA は 150 mAh に対して 0.67C。

> **1枚目の実機で PROG のパターンが断線していた。** 症状は「充電ランプが点かない、
> かつ充電もされない」。MCP73831 は **PROG がオープンだと定義されたシャットダウン
> 状態に入る**（データシートに `PROG Floating` 条件の行が独立してある:
> R_PROG の充電範囲は 2〜67 kΩ、**70〜200 kΩ 以上でシャットダウン**、そのとき
> I_SS 25 µA / I_DISCHARGE 0.15 µA）。
>
> 切り分けは `tools/battery_log.py` で電圧の傾きを見るのが確実だった。STAT は
> D8 にしか繋がっておらず **MCU からは読めない**ので、ファームから充電状態を
> 知る手段は電圧しかない。実測値:
>
> | | 傾き |
> |---|---|
> | 断線時（75分・148サンプル） | **-3 mV/hour** |
> | リワーク後 | **+851 mV/hour** |
>
> ±6 mV の振れは ADC の量子化ノイズ（電池換算 1.76 mV/LSB）なので、
> 数サンプルの上下動を「上がっている」と読まないこと。傾きで見る。

### バッテリ電圧が読める（旧基板の設計ミスが直っている）

BAT_CHECK が **P0.28 = AIN4** に来ているので ADC が取れる。分圧は R10/R11 の
1M+1M で 1:1、C11 10 nF でフィルタ。4.2 V → 2.1 V なので SAADC の 1/6 ゲイン
（フルスケール 3.6 V）に収まる。

分圧の値は **v2 で 10M + 10M に変更**した（KiCad 反映済み・未製造。**手元の3枚は
1M+1M**）。比が 1:1 のままなので**ファームは無変更**
（DTS の `battery-divider-num/den` が 2/1 で、そこに値そのものは入っていない）。

| | 常時消費 | 寿命 |
|---|---|---|
| 1M + 1M | 1.9 µA | 281 日 |
| **10M + 10M** | **0.19 µA** | **305 日 (+8%)** |
| 完全に遮断（MOSFET 等） | 0 µA | 307 日 (+9%) |

**完全に遮断しても 10M+10M に対して +2 日しか変わらない**ので、ゲーティング回路を
足す価値は無い。10M は JLCPCB の Basic（C26082）で、0402 の Basic 抵抗で 1MΩ 以上は
1M と 10M の2つだけなので、実質この一択。

> **10M+10M にしたら精度を実測で確認すること。** ソース抵抗が 5 MΩ になり、
> nRF52840 SAADC の表（取得時間 40 µs で 800 kΩ まで）を素直に読むと規格外になる。
> C11 10 nF があるのでサンプリング容量はそこから電荷を分けるだけ（誤差 2.5pF/10nF =
> 0.025%、C11 の再充電は τ = 50 ms で 60 秒周期に対して余裕）だが、**SAADC の入力
> リーク電流だけは数値を持っていない**。1 nA 流れれば 5 MΩ に対して 5 mV、電池換算
> 10 mV のオフセットになる。テスターの実測と `s` の表示を充電中に数点比べれば分かる。

ファーム側は `src/battery.c` が 60 秒ごとに 8 サンプル平均で読み、Battery Service に
流している。`ble_csc_init()` が置く `BATTERY_DEBUG_PERCENT` = 50 は「まだ誰も測って
いない」を表す初期値で、測れる基板では起動から 1 秒以内に実測値で上書きされ、
測れない基板（ブリングアップ機）ではそのまま残る。

## ブリングアップ基板: RideFormTracker PCB **v1.0**（board = `cadence_rft`）

本番基板ができるまではこれを流用する。実体は
`2026/2026-02-28_RideFormTracker/apps/v2/HARDWARE.md` の v1.1 と同じ基板なので、
詳細（電源・充電まわり・SWD トラブルシュート）はそちらが一次資料。
FindMyTag の `findmy_rft` とも同じ基板で、ピンも配置も同一。

ここには **ケイデンスセンサーが実際に使うピンだけ** 載せる。

### 使うピン

| nRF52840 | パッド | 信号 | 接続先 |
|---|---|---|---|
| P0.06 | 22 | SPI MOSI | LSM6DSV SDA/SDI |
| P0.04 | 20 | SPI MISO | LSM6DSV SDO/SA0 |
| P0.08 | 24 | SPI SCLK | LSM6DSV SCL/SPC |
| P1.09 | 26 | SPI CS | LSM6DSV CS |
| P0.26 | 19 | IMU_INT1 | LSM6DSV INT1（wake-up） |
| P0.05 | 21 | IMU_INT2 | LSM6DSV INT2（未使用） |
| P0.28 | 13 | LED_R | RGB LED 赤（共通アノード＝アクティブ LOW） |
| P0.31 | 12 | LED_G | RGB LED 緑 |
| P0.30 | 14 | LED_B | RGB LED 青 |
| P0.00/P0.01 | 17/18 | XL1/XL2 | 32.768 kHz 水晶 |
| D+ / D- | 35/34 | USB | USB-C |
| SWDIO/SWCLK | 51/53 | SWD | U5 ヘッダ（初回書き込み用） |

### v1.0 と v1.1 の違い

このファームから見て**違うのは RGB LED のピンだけ**。SPI・両 INT・水晶・USB・SWD は
v1.0/v1.1 共通（RideFormTracker の HARDWARE.md で "same on v1.0 and v1.1" と
明記されている）。

| 信号 | **v1.0（いまこれ）** | v1.1 |
|---|---|---|
| LED_R | **P0.28**（パッド 13） | P0.30（パッド 14） |
| LED_G | **P0.31**（パッド 12） | P0.29（パッド 10） |
| LED_B | **P0.30**（パッド 14） | P0.31（パッド 12） |

v1.1 では P0.28 が磁気センサーの I2C SDA に変わっているので、ここは本当に
リビジョン依存。とはいえ間違えても失うのは LED だけで、ケイデンス検出は LED を
一切使わないし、そもそも USB 接続時しか点かない。切り替えは
`boards/nordic/cadence_rft/cadence_rft.dts` の `leds` ノード3行。

### 使わないもの（DTS で明示的に disable）

| 部品 | 理由 |
|---|---|
| W25Q256JVP (QSPI フラッシュ) | 本番基板には載せない。ファームが依存しないよう最初から切る |
| IIS2MDC (磁気センサー, I2C) | ケイデンスには不要 |
| CryptoCell (CC310) | 使わない。エントロピーは `&rng` から取る |
| NFCT | 使わない（P0.09/P0.10 を GPIO に開放） |

> **注意**: `&cryptocell` を disable すると、nrf52840.dtsi のデフォルトの
> `zephyr,entropy` が宙に浮いてビルドが落ちる。DTS の `chosen` で
> `zephyr,entropy = &rng;` を指定してある。

### 32.768 kHz 水晶は必須

CSC Measurement には「最後に1回転した時刻」が 1/1024 秒単位で乗り、サイコンは
**それを微分して RPM を出す**。つまり表示されるケイデンスの精度は、このクロックの
精度そのもの。内蔵 RC は校正しても ±500 ppm、水晶は ±20 ppm。
`cadence_rft_defconfig` の `CONFIG_CLOCK_CONTROL_NRF_K32SRC_XTAL=y` はこのため。

### バッテリ電圧が読めない

BAT_CHECK が P0.09 に繋がっているが、**nRF52840 の AIN は P0.02–P0.05 と
P0.28–P0.31 だけ**なので P0.09 では ADC が取れない。v1.0/v1.1 共通の設計ミス。

そのためファームは Battery Service で常に 100% を返している。本番基板では AIN0/1/3
(P0.02 / P0.03 / P0.05) のどれかに回すこと。回せば `ble_csc_set_battery()` を
呼ぶだけで済む。

### GPIO 電圧

MDBT50Q は UICR の REGOUT0 が未設定（＝消去済み）だと GPIO が 1.8 V で動く。
LSM6DSV の VDD_IO 下限を割るし、共通アノード LED も引けない。
`boards/nordic/cadence_rft/board.c` が起動時に 3.3 V を書いて 1 回だけリブートする。

チップ消去（APPROTECT 解除の mass erase を含む）のあと最初の 1 回だけ、
起動が 2 回走るのはこのため。異常ではない。

なお board.c はブートローダー側にもリンクされるので、`sysbuild/mcuboot.conf` に
`CONFIG_REBOOT=y` が要る（FindMyTag ではシリアルリカバリが REBOOT を連れてきていた
ので気付かれていなかった）。

## 取り付け

センサーは**クランクアームに固定する**。向きは問わない —— ファームが回転面を
自動判定する（AC エネルギーが一番小さい軸をスピンドル軸とみなす）。

効くのは向きより**位置**で、スピンドルからの距離 r が遠心力 w²r を決める:

| 位置 | r | 120 rpm での遠心力 |
|---|---|---|
| ペダル寄り | 0.17 m | 2.7 g |
| クランク中ほど | 0.09 m | 1.4 g |
| スピンドル近く | 0.03 m | 0.5 g |

**スピンドルに近いほど楽**（遠心力が小さく、DC トラッカーの仕事が減る）。ただし
近すぎても得はしない —— 信号は遠心力ではなく重力なので、r に関係なく 1 g のまま。
±8 g レンジは r = 0.17 m・150 rpm（4.3 g + 重力）でも飽和しない値として選んでいる。

取り付けたら USB コンソールの `c` でライブ表示を見ながらクランクを回して、
`amp` が 1000 mg 付近に落ち着くことを確認する。ここが大きくズレる場合、
センサーが回転面に対して傾いているか、固定が緩んでいる。

## 次のリビジョンへの申し送り

### v2 で KiCad に入れた変更（未製造）

**手元の3枚は下の変更が入っていない v1。** ピンアサインは変わらないので
**ファームは無変更**で両方に載る。

```
+V_BAT ── SW2 ── R13 100k ──┬── D2 ──┐
                            │        │
                        SW_READ      ├── LDO_EN ── U9.3 (EN)
                            │        │
                        R15 330k     │
                            │        │
                           GND       │
                                     │
+5V ── R16 100k ──┬── D4 ────────────┤
                  │                  │
              R17 100k               │
                  │      SOFT_LATCH ─┴─ R12 100k
                 GND
```

**1. BAT_CHECK の分圧を 1M+1M → 10M+10M**（R10/R11、C26082）
常時 1.9 µA → 0.19 µA。比は 1:1 のままなので DTS の `battery-divider-num/den`
も無変更。**要実測**（上の「バッテリ電圧が読める」節の注意を参照）。

**2. R13 を SW2 の直後へ移動**
これが効く。既存の SW_READ 分圧（100k/330k）が、そのまま **EN へ入る電圧の降圧も
兼ねる**ようになる。EN はボタン押下時に 3.95 V → **2.97 V**。SW_READ の分圧比は
変わらないので読み取りも電池消費（押下中 9.8 µA）もそのまま。**部品ゼロ追加。**

**3. VBUS を 100k/100k で分圧して D4 経由で LDO_EN へ**（R16/R17/D4）
USB を挿すだけで起動するようになる。低電圧カットオフで落ちた後も、USB を挿せば
充電しながら基板が立ち上がる。

結果、**EN に乗る電圧が全ソースで VDD 以下に収まる**:

| ソース | EN |
|---|---|
| USB 分圧 | 2.25 V |
| ボタン（VBAT 4.2 V） | 2.97 V |
| GPIO via R12 | 3.30 V |

分圧が要る理由は EN の耐圧ではない。**EN 自体は 6.0 V まで定格内**。困るのは R12 の
先にいる P1.11（VDD 3.3 V）で、EN が 4.5 V になると GPIO の absolute maximum
（VDD + 0.3 V）を破って出力段を逆駆動する。実害は数 µA で出にくいが、**abs max を
超えた時点でベンダーの保証が消える**。

ダイオードの Vf で落とす案は成立しない。**Vf は電流の強い関数**で、I_EN = 10 nA では
シリコンでも 0.2〜0.3 V しか出ない。mA 域の「Vf 2 V」はここには現れない。

値を決めているのは分圧比ではなく **LDO の smart enable pulldown 500 kΩ**。起動時は
EN が閾値以下なのでこれが効いており、分圧のテブナン抵抗が 500 kΩ と張り合えないと
立ち上がらない。100k/100k なら Rth 50 k、VBUS 最低 4.75 V でも起動時 1.93 V。

**GPIO の枝にはダイオードを入れていない。** 3本とも通せば見た目は対称な wired-OR に
なるが、それをやると GPIO が EN を**引き下げる**能力を失う。いまの電源 OFF は R12 を
通した能動放電（τ = 1 µs）で、リークに対して桁違いに強い。OR にするならプルダウンが
要り、するとリセット中の EN 保持が 2 ms → 100 µs に縮んで board.c が間に合わなくなり、
今度は EN にコンデンサが要る。**検証済みの挙動を2つ動かすことになるので採らなかった。**

R17 は 200k にすると余裕がさらに増える（GPIO で引いたときの EN が 1.50 V → 1.85 V）が、
**100k は R12/R13/R16 と同じ品番で BOM の行が増えない**ためこちらを選択。330k 以上は
EN が VDD を超えるので不可。

### まだ開いている項目

- **EN ノードに 1 µF**。電池運用時のリセット対策。board.c のラッチで足りている
  可能性が高い（実機で `r` も USB 更新も通った）ので、優先度は低い
- **EN–GND のプルダウン**。今はソフト実装で代替している。入れるなら 10 M
  （0.33 µA。1 M だと 3.3 µA で予算の 17%、4.7 M は JLCPCB の Basic に無い）
- **コイン電池化**。充電回路と LDO が消えるぶん体積が大きく減り、LiPo の自己放電と
  保護 IC（DW01 系 3 µA）も消える。予算の内訳では「電池自体」が 33% を占める
  - CR2032 なら約 700 日（モデル値）。CR1632 は 396 日で、18×21 mm のオーバル基板に
    収まる。ただし基板とセルを重ねるとアンテナがデチューンするので、アンテナ側を
    セルの外にはみ出させること
- クランクへの固定方法（バンド / 両面テープ / 3Dプリントのクランプ）
